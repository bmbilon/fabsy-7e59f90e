# Required portal lookup identifier

New representation checkouts require one valid client-confirmed licence plate, driver's licence number or DOB. The public `/checkout`, `/consent` and `/payment` paths save that value privately before creating a service order. The private saved-ticket checkout checks existing DOB/DL data or asks for one identifier after storing the actual signed authorization. The photo-upload flow already requires the same private case lookup step before payment.

Migration `20261008234500_required_portal_lookup` was individually applied and registered in production project `gcasbisxfrssonllpqrw`. It gates representation service-order inserts and ticket checkout reservations before the existing Stripe creation call, retains historical completed-payment reconciliation, and leaves report-only orders unaffected. The existing general payment endpoints were not redeployed; the scoped `initial-disclosure-agent` broker was deployed from an isolated directory with its lookup helpers.

Order values are encrypted with a distinct order AAD and owned by a random UUID/private capability. Client status returns only a boolean. An agent import verifies the frozen claim hash and transfers it only through exact normalized ticket identity or that order's original verified upload, checking current source path/bytes again. Name or email matching alone cannot transfer an identifier. These records do not replace signer authority, payment, consent, government-session terms or exact-ticket receipts.

At 23:11 UTC the live database tests rejected missing identifiers for both service orders and ticket checkout reservations inside a rolled-back transaction. The installed gates and private table permissions were verified. Actual anonymous-capability API checks confirmed rejection of placeholder plate/DL values, future DOB, unchecked confirmation and invalid capabilities; anonymous government terms acceptance remained blocked. No synthetic orders, lookup records, payments or portal sessions were created by those checks.

Verification: 25 universal/private checkout tests, 43 photo/complete-ticket tests, 14 Deno source/consent/lookup tests, actual PostgreSQL 17 gate/session/receipt suites, frontend TypeScript with ES2022/DOM declarations, scoped broker type-check and the default Vite build passed. The CI workflow also runs the lookup and filing-evidence tests.

The public frontend release uses the existing backend-first, pinned-commit Cloudflare Pages workflow. Existing hosted Stripe URLs are not retroactively cancelled.
